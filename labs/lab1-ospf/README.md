# lab1 스위치 2대를 OSPF로 잇기

## 이 실습에서 배우는 것
- 스위치 2대를 선 하나로 잇고, 서로의 주소를 OSPF로 저절로 알게 만듦  
- 주소를 사람이 하나씩 적는 방식(static 경로)과 달리, 스위치가 자기 주소를 이웃에게 알려 주고 이웃의 주소를 배움  
- 첫 실습이라 비교할 앞 실습은 없음. 이후 lab2 ~ lab4가 이 실습 위에 쌓임

## 구성도와 주소표
```text
   +----------------------+                    +----------------------+
   | sw1                  |                    | sw2                  |
   | lo   10.0.0.1/32     |                    | lo   10.0.0.2/32     |
   |                      |                    |                      |
   | eth1 192.168.12.1/30 |-------- 선 --------| eth1 192.168.12.2/30 |
   +----------------------+                    +----------------------+
              OSPF 영역(area) 0 안에서 서로 주소를 알려 줌
```

| 장비 | 인터페이스 | 주소 | 역할 |
|------|-----------|------|------|
| sw1 | lo | 10.0.0.1/32 | 장비의 대표 주소(루프백) |
| sw1 | eth1 | 192.168.12.1/30 | sw2와 잇는 선 |
| sw2 | lo | 10.0.0.2/32 | 장비의 대표 주소(루프백) |
| sw2 | eth1 | 192.168.12.2/30 | sw1과 잇는 선 |

- 컨테이너 이름은 `clab-lab1-sw1`, `clab-lab1-sw2`임

## 준비물
- Docker Desktop이 켜져 있어야 함(트레이의 고래 아이콘이 "running" 상태)  
- Windows 터미널(또는 PowerShell)을 열고 `wsl`을 입력해 WSL을 엶  
- 실습 폴더로 이동함. 아래 `<사용자>`는 내 Windows 사용자 이름으로 바꿈  
  ```bash
  cd /mnt/c/Users/<사용자>/class/aidc/labs/lab1-ospf
  ```
- 다른 실습(lab2 등)이 떠 있으면 컴퓨터 자원을 아끼려고 해당 실습 폴더에서 끄고 시작함

## 따라 하기
1. 실습 환경을 띄움  
   ```bash
   ./reset.sh
   ```
   이렇게 나오면 성공: `다시 띄웠습니다...` 뒤 15초 정도 기다리면 검사 결과가 나오고 마지막 줄이 `결과: 모두 통과`임  
   (`reset.sh`는 한 번에 25초쯤 걸림)  
   ```text
   다시 띄웠습니다. OSPF가 붙을 때까지 15초 기다립니다...
   1) 두 스위치가 OSPF 이웃(Full)이 되었는가
     [통과] sw1: 이웃 1개가 Full 상태
     [통과] sw2: 이웃 1개가 Full 상태
   2) 상대 루프백을 OSPF로 배웠는가
     [통과] sw1: 10.0.0.2/32 를 OSPF로 배움
     [통과] sw2: 10.0.0.1/32 를 OSPF로 배움
   3) 루프백끼리 통신되는가
     [통과] sw1(10.0.0.1) -> sw2(10.0.0.2) 통신 정상
     [통과] sw2(10.0.0.2) -> sw1(10.0.0.1) 통신 정상

   결과: 모두 통과
   ```
   뜻: `reset.sh`는 처음 상태로 지우고 다시 띄운 뒤 검사(`check.sh`)까지 한 번에 돌려 줌.  
   이미 떠 있어도 그대로 다시 띄우므로, 아래 2 ~ 4번은 이 뒤에 하나씩 눈으로 확인하는 단계임

2. 이웃을 찾았는지 확인함  
   ```bash
   docker exec clab-lab1-sw1 vtysh -c "show ip ospf neighbor"
   ```
   이렇게 나오면 성공: 한 줄이 나오고 `State`가 `Full/-`임(시간 값은 바뀔 수 있음)  
   ```text
   Neighbor ID     Pri State           Up Time         Dead Time Address         Interface
   10.0.0.2          1 Full/-          15.436s           34.563s 192.168.12.2    eth1:192.168.12.1
   ```
   뜻: sw1이 sw2(10.0.0.2)를 이웃으로 찾았고, 서로 가진 길 정보를 완전히 맞췄다는 뜻(`Full`)임

3. sw1이 sw2의 주소를 배웠는지 확인함  
   ```bash
   docker exec clab-lab1-sw1 vtysh -c "show ip route 10.0.0.2/32"
   ```
   이렇게 나오면 성공: `Known via "ospf"`가 보이고, 다음 길이 `192.168.12.2, via eth1`임  
   ```text
   Routing entry for 10.0.0.2/32
     Known via "ospf", distance 110, metric 10, best
     * 192.168.12.2, via eth1, weight 1
   ```
   뜻: 이 길은 내가 적은 것이 아니라 OSPF가 sw2에게서 배운 것임. `ospf` 대신 `static`이 보이면 손으로 넣은 길임

4. 대표 주소끼리 통신해 봄  
   ```bash
   docker exec clab-lab1-sw1 ping -c 3 -I 10.0.0.1 10.0.0.2
   ```
   이렇게 나오면 성공: `3 packets transmitted, 3 packets received, 0% packet loss`  
   뜻: sw1의 대표 주소(10.0.0.1)에서 sw2의 대표 주소(10.0.0.2)로 갔다가 돌아오는 길이 양쪽 모두 열려 있음

5. 검사를 돌림  
   ```bash
   ./check.sh
   ```
   이렇게 나오면 성공: 항목 3개가 모두 `[통과]`이고 마지막 줄이 `결과: 모두 통과`임(1번의 출력과 같은 모양)  
   뜻: ping이 된다는 것만이 아니라 "이웃이 Full이고, 상대 루프백을 OSPF로 배웠는가"까지 확인함

6. 실습 환경을 끔  
   ```bash
   ./clab.sh destroy -t lab1.clab.yml --cleanup
   ```
   이렇게 나오면 성공: `Removed container` 줄이 2개 보임  
   ```text
   INFO Destroying lab name=lab1
   INFO Removed container name=clab-lab1-sw1
   INFO Removed container name=clab-lab1-sw2
   ```
   뜻: 컨테이너를 지우고 실습 폴더 안의 임시 폴더(`clab-lab1`)도 지움

## 고장 연습
`./fault-demo.sh`는 고장을 하나씩 내고 `check.sh`를 돌린 뒤 바로 원래대로 되돌림. 마지막에 `복구 확인`으로 다시 검사함  
(아래 표는 2026-11-23 강사 PC에서 `fault-demo.sh`를 실제로 돌린 결과임)

| 번호 | 일부러 내는 고장 | 실패로 잡힌 검사 | ping |
|------|------------------|------------------|------|
| 1 | sw1과 sw2 사이 선을 끊음 | 1번(sw1, sw2), 2번(sw1, sw2), 3번 | 안 됨 |
| 2 | sw2가 선(192.168.12.0/30)을 OSPF에 넣지 않음 | 1번(sw2), 2번(sw2), 3번 | 안 됨 |
| 3 | sw2의 hello 간격만 5초로 바꿈 | 1번(sw2), 2번(sw2), 3번 | 안 됨 |
| 4 | sw2 선 주소를 오타 냄(192.168.12.2 를 192.168.13.2 로) | 1번(sw2), 2번(sw2), 3번 | 안 됨 |
| 5 | 루프백을 OSPF에서 빼고 static 경로로 통신만 살림(편법) | 2번(sw1, sw2: OSPF가 아니라 static으로 들어옴) | 됨 |

- 5번은 ping이 되는데도 검사는 실패함. 통신은 살렸지만 이 실습의 목표인 OSPF를 쓰지 않았기 때문임  
- 2 ~ 4번은 sw2 쪽이 먼저 실패한 순간의 출력임. sw1 쪽은 이웃 시간 초과(dead timer)가 지나야 실패로 바뀜  
- 마지막 `복구 확인`은 `결과: 모두 통과`로 끝남(고장을 모두 되돌렸다는 뜻)

## 막혔을 때
1. Docker Desktop이 켜져 있는지, `docker ps`에 `clab-lab1-`로 시작하는 컨테이너 2개가 있는지 확인함  
2. `./check.sh`에서 1번이 실패하면 띄운 지 15초가 안 지났을 수 있으므로 잠시 기다린 뒤 다시 돌림  
3. 이웃이 안 맺어지면 `docker exec -it clab-lab1-sw1 vtysh`로 들어가 `show ip ospf neighbor`를 확인함(나올 때는 `exit`)  
4. 실패 항목 아래에 나오는 `힌트:` 줄을 읽고 그대로 따라 해 봄  
5. 두 번 시도해도 안 되면 `./reset.sh`로 처음 상태로 되돌림

## 용어 풀이
| 용어 | 쉬운 말 |
|------|---------|
| 스위치 | 네트워크 장비를 서로 잇는 장비. 이 실습에서는 컨테이너 안의 FRR 프로그램이 스위치 역할을 함 |
| FRR | 리눅스에서 스위치의 길 찾기 기능을 해 주는 프로그램 |
| 컨테이너 | 한 컴퓨터 안에 따로 칸을 막아 돌리는 작은 가상 컴퓨터 |
| 인터페이스(eth1) | 장비에 달린 선 꽂는 구멍의 이름 |
| 루프백(lo) | 장비 안에 있는 가상의 구멍. 선이 끊겨도 꺼지지 않아서 장비의 대표 주소로 씀 |
| /30, /32 | 주소 뒤에 붙는 숫자로, 같은 망에 묶이는 주소 개수를 정함. /30은 장비 2대용, /32는 주소 한 개 |
| 라우팅(경로) | 목적지로 가려면 어느 이웃에게 넘길지 적어 둔 길 안내 |
| static 경로 | 사람이 직접 적어 넣은 길 안내 |
| OSPF | 이웃끼리 자기가 아는 길을 주고받아 길 안내를 저절로 만드는 방식 |
| 영역(area) | OSPF에서 함께 길을 나누는 장비들의 묶음. 이 실습은 area 0 하나뿐임 |
| 이웃(neighbor) | 선으로 이어져 서로 길을 주고받기로 한 상대 장비 |
| Full | OSPF 이웃 상태 중 가장 끝 단계. 서로 가진 길 정보를 완전히 맞춘 상태 |
| hello 간격 | OSPF 장비가 "나 여기 있다"는 인사를 보내는 주기. 양쪽이 다르면 이웃이 맺어지지 않음 |
| dead timer(이웃 시간 초과) | 이웃의 인사가 이 시간 동안 오지 않으면 이웃이 끊겼다고 보는 제한 시간 |
| vtysh | FRR 스위치 안에 들어가 상태를 보고 설정하는 명령 도구 |
